## Purpose and master-plan alignment

The prior W0–W5 packet established useful controls, schemas, and design documents.
It is not the substantive end-of-week update. A slot shell is not a point-in-time
corpus; an ADR is not a cross-runtime audit; fixture metadata is not Agent 4 shadow
evidence; and a dossier outline is not an implementation-ready safety release.

This plan raises the offline standard without changing the master plan:

- Phase 0 remains at 0/5; only signed runtime observation can advance it.
- Phase 1 preparation may continue, but Q-001–Q-004 remain human-owned blockers.
- Phase 2/3 artifacts remain local; no durable write, vendor, score activation, or
  historical-result claim is authorized.
- Agent 4 remains shadow-only. Phase 5 remains reader-first coordinated lineage
  work. Every S1/S2 item remains a separate reviewed release after observation.

## B. Real local Bench-30 corpus

Replace placeholders with thirty locally preserved, cited packets. Each slot needs:
security/share-class identity; decision, availability, and retrieval times; receipt
hash; source tier and retention note; policy/scoring version; raw expected facts and
missingness; restatement/corporate-action/conflict state; and a predeclared expected
result (review-ready, blocked-missing, blocked-stale, blocked-conflict, or excluded).

Minimum coverage: 12 ordinary companies, 2 banks, 2 insurers, 2 REITs, 3 thin/missing
coverage cases, 3 stale-estimate cases, 2 restatements, 2 share-class/corporate-action
traps, and 2 negative/conflict/future-fact cases. Overlap must be explicit.

Freeze each packet hash, reject changed packets, validate chronology and source
classification, and emit only coverage/missingness/conflict distributions. If fewer
than thirty permitted local packets exist, ship the verified subset and the gap list;
do not call it Bench-30.

## D. Agent 4 paired-shadow laboratory

Create a versioned draft policy; every numeric field must be explicitly owned or
marked policy-unresolved. Use at least twelve immutable paired records across all
specialists: accepted-within-bound, duplicate thesis, concentration/cash/gross/budget
breaches, stale/mismatched snapshots, owned/unowned SELLs, differing horizons, Sam
disagreement, and policy-unresolved abstention.

Each record fingerprints proposal, portfolio/allocation snapshots, policy version,
Agent 4 result, virtual effect, and Sam label. Reruns must be deterministic. No
record may carry approval HMAC, order intent, queue mutation, or cash reservation.
Report policy coverage and agreement/disagreement only, never performance or
promotion readiness.

## Sequencing and review gate

1. Complete A; hold it if purity requires changing live modules.
2. Populate B only from permitted local material; never use a live call to hit count.
3. Complete C and D after their inputs are frozen.
4. Complete E from the audited affected-surface map.
5. Run import/path/secret scans, full tests, manifest-to-diff review, and independent
   review.

The branch is review-ready only when all five packets have substantive evidence or an
explicit hold record; no placeholder is described as evidence; every local tool passes
the dependency denylist; and release notes distinguish offline readiness from push,
merge, deployment, Phase 0 observation, and phase advancement.
